# 자동매매 현황

HTML/CSS/JavaScript + AWS Python 표준 라이브러리 API. ChatGPT 계정이나 Sites에 종속되지 않습니다.
GitHub Pages에는 `docs/`의 화면 코드만 공개하며 금융 데이터·계좌번호·API 키·비밀번호는 포함하지 않습니다.

## 운영

- 프런트엔드: `https://mathtjungsw.github.io/kiwoom-bot-dashboard/`
- API: 기존 AWS HTTPS 호스트의 `/bot-api/` 경로 → 별도 loopback `127.0.0.1:8880`.
- 기존 수기 기록장의 `/api/`와 파일은 수정하지 않습니다. Caddy에 별도 경로만 추가합니다.
- 서비스 `kiwoom-dashboard`, 코드 `/opt/kiwoom-dashboard`.
- 인증 DB `/var/lib/kiwoom-dashboard/auth.db`. 비밀번호 scrypt 해시, 세션 SHA-256 해시만 저장.
- 세션은 로그인 시점부터 정확히 7일. 재시작으로 만료가 연장되지 않으며 로그아웃/비밀번호 변경 시 즉시 무효화.
- 기기 로그인 유지를 위해 불투명 토큰을 localStorage에 저장. 공용 기기 사용 후 로그아웃.
- 외부 스크립트·분석 추적·CDN 의존성 없음. CSP 적용. 허용된 Origin과 인증 토큰을 모두 확인.
- 비밀번호 설정: 서버에서 `sudo -u ubuntu /opt/bots/kiwoom-stock/.venv/bin/python3 -m backend.server password` (작업 디렉터리 `/opt/kiwoom-dashboard`). 화면에 표시되지 않는 입력을 본인이 수행합니다. 재설정 시 기존 세션 모두 폐기.

## 데이터와 제어

봇 JSON 및 `mode=ro` SQLite만 읽으며 키움 API를 호출하지 않습니다. 계좌 샘플의 보유 종목을 모두 표시하고 상태가 불일치하면 트레일 값을 보류합니다.
시세의 출처, 봇 관측 시각, 지연, 추정/미확인 손익을 구분합니다. 체결 확인 없는 주문 로그를 확정 수익으로 표시하지 않습니다.
계좌 총자산/예수금은 계좌 샘플 시점 값, 평가손익은 표시된 관측 가격 기준의 비용 차감 전 값입니다.
화면은 5초, 서버 캐시는 2초, 무거운 거래/전략 집계는 60초 캐시. 기존 DB를 웹용으로 복제하거나 별도 시세 요청을 늘리지 않습니다.
분석은 네 전략이 모두 종료한 동일 진입만 비교하고 신규 진입/기존 보유를 분리합니다. 직접 매도 60%는 종합 보고 귀속 기준이며 원본 손익을 변조하지 않습니다.

중지 버튼은 `/var/lib/kiwoom-dashboard-control/command.json`에 원자적으로 요청만 기록합니다. 봇이 읽어 저장한 확인 ID와 일치해야 중지 확인을 표시합니다.
중지 시 매수와 매도 감시 모두 멈추며 기존 주문은 취소되지 않습니다. 재개 버튼/매매 주문 API는 없습니다.
재개는 서버 관리자가 로컬 제어 JSON을 `{"id":"local-admin-resume","paused":false}`로 원자적 교체해야 합니다.
제어 파일이 없거나 손상되면 봇은 안전상 중지합니다. 웹 API 중단만으로 기존 제어 상태를 변경하지 않습니다.
구글시트는 조회·기록·제어 호출을 모두 해제하되 서버 분석 로그와 거래 outbox 기록은 계속 유지합니다.

## 수정과 테스트

### 종목 소개와 뉴스

보유 종목명을 누르면 공식 홈페이지의 짧은 소개문과 네이버 최신순 뉴스 검색 결과 최대 3건이 별도 상세창에 표시됩니다. 공식 홈페이지 주소·업종·주요제품은 KIND 상장법인목록을 종목코드로 연결합니다. 홈페이지 소개문은 사이트가 공개한 description 메타데이터만 표시하며 robots.txt를 준수합니다. 미리 공식 홈페이지·기업 공시를 확인해 저장한 사업소개 요약이 있으면 그 출처와 원래 확인일을 유지해 우선 표시합니다. 이 검토 자료는 비공개 서버 카탈로그에만 보관하며 공개 저장소에 보유 종목 목록을 올리지 않습니다. 확인되지 않은 홈페이지나 소개문은 임의 추정하지 않으며, 접속 실패 시 출처를 구분한 기본정보만 표시합니다. 새 보유 종목도 같은 방식으로 조회하지만 공식 자료가 없는 회사의 상세 소개문을 자동으로 만들어내지는 않습니다. AI/LLM API 호출, 운영 중 자동 요약 생성, 기사 본문 다운로드는 없습니다.

공식 홈페이지 조회는 월 단위 캐시, 하루 10개/월 100개 한도, HTTPS 인증서 검증 및 공인 IP 고정 연결을 사용합니다. 현재 보유에 맞춘 정보만 인증 API로 제공하며 사용자 지정 URL은 받지 않습니다. 기업 캐시는 최대 200개, 뉴스는 30분 후 삭제하므로 누적 보관하지 않습니다. 서버 증설·유료 데이터 계약 없이 기존 EC2에서 실행합니다. 추가 저장·전송량이 아주 작다는 예상이지 AWS 요금이 절대 0원 증가한다는 보장은 아닙니다. NAVER API HUB는 2026-10-19 확인 기준 한시적 무료이며, 향후 요금 변경 시 별도 재검토가 필요합니다. 호출 한도는 비용 0원 보장 장치가 아닙니다.

`/bot-api/company/<보유종목코드>`는 기존 로그인 후에만 접근할 수 있습니다. 웹 요청은 작은 캐시 파일을 읽고 공개 기업명/종목코드로 작업을 등록할 뿐, 외부 API를 기다리지 않습니다. `kiwoom-company-info.path`가 별도 oneshot 작업을 실행하며, CPUQuota 10%, MemoryMax 64M, Nice 19와 거래 프로젝트/인증 DB/제어 파일 접근 차단을 적용합니다. 자동매매 서비스나 전략에는 변경이 없습니다. 같은 EC2의 물리 자원을 공유하므로 지연이 절대 0이라고 보장하지는 않습니다.

뉴스는 NAVER API HUB의 뉴스 API만 사용합니다. 검색어는 회사명만 보내며 보유 여부·수량·가격·수익률·계좌번호는 보내지 않습니다. 검색 결과 순서와 제목 의미를 변경하지 않고 출처/링크/제공일을 표시합니다. 본문, 이미지, AI 요약, 뉴스 기반 매매 판단은 사용하지 않습니다. 30분 임시 캐시는 만료 후 제공하지 않으며 15분 간격의 정리 타이머로 삭제합니다. 실패 시 5분간 재시도를 제한하고 웹 창은 결과 대기를 제한된 횟수만 확인합니다.

키는 서버에서 `sudo python3 deploy/configure_news.py`의 숨김 입력으로 직접 설정합니다. `/var/lib/kiwoom-dashboard-info/provider.json`(0600)에 보관되며 화면 API/GitHub/로그에는 포함하지 않습니다. 새 뉴스 앱의 네이버 콘솔 한도는 일 100회·월 3,000회로 설정하고, 작업기 자체는 일 90회·월 2,700회에서 중단합니다. 현재 API HUB는 한시 무료 안내이며 향후 유료 정책은 별도 확인해야 합니다. 서버/디스크 증설과 유료 AI 호출은 필요하지 않습니다.

`deploy/update_company_info.py`는 현재 운영 코드 확인, 백업, Python 테스트 후 정보 서비스/API만 반영합니다. 실제 기업/뉴스 연결, 인증, 봇 소스 해시와 PID를 검증하며 실패 시 웹 코드를 복구합니다. 기존 수기 기록장·프록시·보안그룹은 변경하지 않습니다.

### 누적 성과와 보유분 지표

투입금은 공개 화면 코드가 아닌 서버의 보호된 인증 DB 설정에 보관합니다. 서버에서 `python3 -m backend.server capital --initial-capital <최초투입금> --net-external-flows <추가순입출금>`으로 설정합니다. 금액 변경은 로그인 세션을 폐기하지 않습니다.
누적손익은 증권사 추정자산에서 순입금액을 뺀 값이며, 누적수익률은 이를 순입금액으로 나눈 단순 수익률입니다. 매수·매도 대금을 입출금으로 중복 집계하지 않습니다. 주문가능현금도 추정자산에 다시 더하지 않습니다.
총매입·총평가·보유손익·보유수익률은 현재 보유분만 집계합니다. 총평가는 표시 시세 기준, 추정자산은 계좌 조회 시점 기준으로 서로 다를 수 있습니다. 종목별 손익의 세금·수수료 계산은 변경하지 않습니다.
트레일링 중/완충 종목에는 저장 최고가와 실제 스톱가 각각의 평단 대비 수익률을 표시합니다. 표시 스톱 수익률은 체결 보장이 아니며, 기존에 확보한 높은 스톱도 임의로 낮춰 재계산하지 않습니다.
`deploy/update_summary.py`는 운영 소스 확인·백업·테스트 후 대시보드 서비스만 갱신합니다. 자동매매 봇은 수정/재시작하지 않으며, 실패하면 웹 코드와 인증/설정 DB를 복구합니다. 사용 전 운영 상태를 확인하세요.

`docs/` 변경을 main에 push하면 GitHub Pages에서 반영됩니다. 다른 GitHub 계정은 저장소 협업 권한 또는 fork/PR로 수정할 수 있습니다.
서버 코드 변경은 검증 후 별도 반영이 필요합니다. GitHub에 서버 설정/인증 DB/원본 거래 DB를 올리지 마세요.

```sh
python3 -m unittest discover -s tests -v
python3 -m py_compile backend/server.py backend/reader.py
node --check docs/app.js
python3 -m http.server 8766 --bind 127.0.0.1 --directory docs
```

로컬 `http://127.0.0.1:8766/?demo`에서 합성 예시를 확인할 수 있습니다. 운영 도메인에서는 demo 모드가 동작하지 않습니다.
정적 아이콘은 Lucide 라이브러리에서 생성하고 라이선스를 포함합니다.
서버/봇 변경 전 백업, 문법검사, 제한된 단위테스트, 서비스 및 HTTPS 확인을 수행합니다. 실패하면 이전 코드/프록시 설정으로 복구합니다.
